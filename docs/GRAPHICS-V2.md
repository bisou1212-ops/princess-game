# 그래픽 2차 업그레이드 계획 (첫 버전 이후)

아이 반응: 부탁 해결은 즐거워하지만 그래픽이 아쉬움.
부모 의견: **캐릭터·배경·색감과 빛·움직임과 연출** 네 가지 모두 아쉬움.

지켜야 할 것 (CLAUDE.md): 중급 태블릿 30fps, 화면 삼각형 10만 이하, 첫 로딩 10MB 이하, CC0 에셋만, 7세 조작(톡·끌기).

## 지금 그래픽이 단순해 보이는 이유
- **모양:** 모든 모델을 Blender 스크립트로 구·원기둥·원뿔을 붙여 만들었다. 실루엣이 동글동글하지만 디테일이 없다.
- **질감:** 텍스처(그림 질감)가 하나도 없다. 색 하나짜리 재질뿐이라 플라스틱 장난감처럼 보인다.
- **움직임:** 동작은 4개(가만히·걷기·폴짝·손 흔들기)뿐이고, 표정이 없다(입이 늘 같음).
- **배경:** 소품 수가 적고 땅이 평평한 한 가지 색이다.

## 방법 비교

| | 무료 (지금 도구로) | 유료 (AI 3D 생성) |
|---|---|---|
| 캐릭터 | Blender 스크립트를 크게 손봄: 매끈한 몸(서브디비전), 얼굴 윤곽·코·입, 머리카락 가닥, 옷 주름·레이스 | Meshy 같은 AI로 그림처럼 정교한 캐릭터 생성 + 자동 뼈대·동작. 계정과 크레딧(유료)이 필요하고, 옷 갈아입기(부위별 모델)와 맞추기가 어려움 |
| 배경 | CC0 에셋 팩(Kenney·Quaternius: 나무·꽃·집·울타리)을 내려받아 교체 + Poly Haven CC0 텍스처(풀·흙·나무결) | 장소 전체를 AI로 생성. 품질이 들쭉날쭉하고 무거움 |
| 색감·빛 | 텍스처 질감, 구운 그림자(라이트맵), 부드러운 그림자, 노을빛·안개·빛줄기, 색 보정 | 같음 |
| 움직임 | 표정(웃음·놀람·슬픔 눈과 입), 동작 추가(박수·빙글·앉기·하이파이브), 부탁 완료 축하 연출(색종이·빛), 카메라 연출 | 같음 |

**추천:** 무료 방법으로 시작한다. 색감·빛과 움직임·연출은 어차피 코드로 해야 하고, 배경은 CC0 팩으로 바꾸면 효과가 크다. 캐릭터는 먼저 스크립트로 최대한 다듬어 본다. 그래도 아쉬우면 그때 친구·펫처럼 옷을 갈아입지 않는 캐릭터만 AI 생성을 검토한다.

## 진행 순서 (작게 나눠서, 단계마다 배포·확인)
1. **G1 색감·빛:** 땅·벽·나무 텍스처(작은 반복 무늬, KTX2), 구운 그림자, 하늘과 빛 분위기, 색 보정. 효과가 가장 빠르게 보인다.
2. **G2 표정·연출:** 눈·입 표정 바꾸기(대사 mood에 맞춤), 축하 색종이, 동작 3~4개 추가.
3. **G3 배경 에셋:** CC0 팩으로 나무·꽃·덤불·울타리·집 교체, 소품 추가 (삼각형 예산 안에서).
4. **G4 캐릭터 다듬기:** 공주·친구·펫 모델 디테일(얼굴·머리카락·옷).

결정 (2026-11-24): 무료 방법, G1부터.

## Unity로 옮기면?
- **다시 짜야 하는 것:** 게임 코드 전부 (TypeScript → C#). 부탁·대화·옷·가구·펫·저장·화면(UI) 모두 새로 만들어야 한다. 지금까지 한 작업의 대부분이다.
- **그대로 쓸 수 있는 것:** 데이터 JSON(대사·부탁·아이템), Blender 모델(.glb), 기획서.
- **얻는 것:** 편집기에서 보면서 배치, 조명 굽기·후처리 도구, 에셋 스토어.
- **잃는 것:** 웹(WebGL) 빌드는 첫 로딩이 수십 MB로 무겁고, 중급 태블릿에서 느리다. 지금의 "주소만 열면 바로, 10MB 이하" 장점이 사라진다.
- **판단:** 이 게임의 아쉬움(질감·빛·표정·소품)은 Three.js에서도 충분히 고칠 수 있다. 앱스토어 앱으로 크게 키울 때 Unity를 다시 생각한다.

## G1 결과 (색감·빛)
- 표면 무늬 `src/core/surface-patterns.ts`: 마당 돌바닥(어긋난 네모 돌·줄눈), 풀밭 얼룩, 성벽 돌 쌓기, 집 벽 회반죽, 지붕 기와, 나뭇결, 잎 덩어리, 흙·바위 점 — 텍스처 파일 없이 셰이더로 (용량 0)
- 조명: 하늘빛을 줄이고 햇빛을 따뜻하고 세게(그림자·입체감), 주변 반사 0.5
- 색 보정: Neutral 톤 매핑 뒤 채도 +16%, 어두운 곳 보랏빛·밝은 곳 따뜻하게, 중간 대비 (`renderer.ts` CustomToneMapping — 빛번짐 꺼도 적용)
- 바랜 땅·잎 색을 조금 진하게 (`env-models.ts` TINT)
- 발밑 그림자 (공주·친구·펫), 화면 가장자리 살짝 어둡게(CSS)
- 풀 덤불 `grass-tufts.ts`: 풀밭 위 1000개(기본 품질 400), 바람에 살랑, 그리기 1번·삼각형 5천

## G2 결과 (표정·연출)
- 표정 `src/scenes/castle/face.ts`: 그림 눈(뜬 눈·웃는 눈 ^ ^·슬픈 눈 — 바깥이 처지고 물기) + 그림 입(웃음·활짝·크게 벌림·오·작은 웃음·삐죽), 볼 발그레. 대사 `mood`(normal·happy·excited·curious·shy·sad)에 맞춰 말하는 캐릭터 얼굴이 바뀌고, 읽는 동안 입이 뻐끔뻐끔. 대화가 끝나면 원래 얼굴(우는 친구는 슬픈 얼굴)
- 입 자리: 공주·플로라는 원래 3D 입 자리, 동물 친구는 코 바로 아래 몸 표면. 삐삐(부리)는 눈만
- 고개 자세: 궁금하면 갸웃, 수줍으면 살짝 숙이고 기울임, 슬프면 고개 숙임
- 몸짓(클립 없이 뼈를 돌림, `PrincessAnimator.playGesture`): 박수(신난 대사·정답 카드), 끄덕(기쁜 대사), 빙글(부탁 완료 — 공주), 폴짝(부탁 완료 — 친구)
- 선물 화면 축하 색종이(파스텔 조각·별·하트, CSS라 3D 비용 없음, 움직임 줄이기 설정이면 끔). 공주가 빙글 도는 걸 0.7초 보여 준 뒤 선물 화면
- 고친 것: 불러온 뼈 이름은 점이 빠져서(`armL`) 친구 귀(`ear.L`) 스프링이 그동안 안 움직였음 → 두 이름 모두로 찾음. 믹서가 값이 같으면 뼈를 다시 쓰지 않아 더한 회전이 쌓일 수 있었음 → 매 프레임 클립 자세로 되돌린 뒤 더함
- 비용: 얼굴 판 3장(눈 2 + 입 1)씩, 그림은 캔버스로 한 번 그려 공유. 파일 추가 0
